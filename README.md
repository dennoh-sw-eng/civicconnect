# CivicConnect

A citizen service-request and tracking prototype: React + TypeScript + Vite on the front end, Supabase (Postgres, Auth, Storage) as the backend, Netlify for hosting. All authorization is enforced in the database with Row Level Security and scope-checked SQL functions, not by hiding buttons.

## What works
- Citizen registration (email verification via Supabase), sign in/out, request submission with optional private image (JPEG/PNG/WebP, 5 MB), reference numbers like `CCR-2026-000123` generated by a database sequence, own-request list with status filter and pagination, request detail with a timeline built from `request_events`, follow-up messages.
- Staff (officer, supervisor, admin): dashboard metrics from the database (7/30/90 days), requests by category, searchable/filterable table, status changes with validated transitions and mandatory resolution text, public updates, internal notes (never visible to citizens), department assignment and priority.
- In-app notification rows and an audit log are written by the database for submissions, status changes and assignments.

## Not built yet (known limitations)
Notifications bell/UI and email delivery; admin screens for departments, categories, users and audit logs (manage these in the Supabase table editor, or call `admin_set_user`); CSV export; custom date ranges; service targets and overdue counts; reopening; public tracking by reference; automated tests. Do not use for real citizen data until these, a security review and a data-protection assessment (Kenya Data Protection Act) are done.

## 1. Supabase
1. Create a project at supabase.com.
2. SQL Editor: run `supabase/migrations/001_init.sql`, then `supabase/seed.sql` (departments and categories).
3. Authentication → URL Configuration: set Site URL to your Netlify URL and add `http://localhost:5173/**` and `https://YOUR-SITE.netlify.app/**` to Redirect URLs.
4. Authentication → Providers → Email: keep "Confirm email" on. Under Rate Limits, keep defaults or tighten.
5. Project Settings → API: copy the Project URL and the **anon** key. Never put the `service_role` key in the front end or Netlify build variables.

## 2. Run locally
```
npm install
cp .env.example .env   # fill in the two values
npm run dev            # http://localhost:5173
npm run build          # type-check and production build
```

## 3. GitHub and Netlify
```
git init && git add . && git commit -m "CivicConnect"
git remote add origin https://github.com/YOU/civicconnect.git && git push -u origin main
```
In Netlify: Add new site → Import from Git → pick the repo. `netlify.toml` already sets build command, `dist` publish folder, SPA redirects and security headers. Add environment variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then deploy. Netlify serves HTTPS automatically. Update Supabase redirect URLs with the final site URL.

## 4. Create the first administrator
Register normally in the app, verify the email, then in the SQL editor:
```sql
update profiles set role = 'admin' where id = (select id from auth.users where email = 'you@example.com');
```
Create officers and supervisors the same way, e.g. `update profiles set role='officer', department_id=(select id from departments where name='Water Services') where id = ...;`. Clients cannot set roles: sign-up always creates a citizen, and `profiles.role` is not updatable through the API.

## Roles
| | Citizen | Officer | Supervisor | Admin |
|---|---|---|---|---|
| Own requests, messages | yes | – | – | – |
| Requests in own department / assigned | – | yes | yes (department) | all |
| Change status, notes, public updates | – | yes, within scope | yes | yes |
| Assign department / priority | – | – | yes | yes |
| Internal notes | never | yes | yes | yes |
| Categories, departments, user roles, audit logs | – | – | – | yes |

## Metric definitions
"Open" = Pending + In Progress. "Unassigned" = not resolved and no department. Average resolution time uses only resolved requests with `resolved_at >= submitted_at`. Archived requests are excluded. All metrics run with the caller's RLS scope.

## Security notes
RLS is on for every table; staff writes go through `security definer` functions that check scope and transitions; images are in a private bucket and shown via 5-minute signed URLs; storage enforces MIME type and size server-side; audit logs are admin-read-only. The anon key is public by design. Before going live, test policies with a second citizen account.

## Free-tier limits (verify current terms)
Supabase free projects pause after a period of inactivity, have limited database/storage size and a low built-in email rate limit (configure your own SMTP for real use). Netlify's free plan has monthly build-minute and bandwidth limits.

## Backups
Free Supabase has no managed point-in-time restore. Export regularly with `supabase db dump` or `pg_dump` using your connection string, and back up the storage bucket separately.
